# 09: Labels — config, startup check with an error, setup command, guide

**What to build:** Operator decision 2026-10-01: dark-factory works from **labels**, and a missing label is an error, never silently created. (1) Config (`packages/core/src/config.js`, on top of ticket 01): `github.labels` = `{ in, working, needsInfo, done }`; `in` (the label a collaborator puts on an issue to hand it to Shiftwork) is **required** whenever a `github` block exists — missing → config error `github.labels.in: required: the label that hands an issue to Shiftwork (see docs/guide.md "Dark-factory: labels")`; the others default to `shiftwork:working`, `shiftwork:needs-info`, `shiftwork:done`; every value a non-empty string. (2) `checkLabels({ github, config })` in `packages/cli/src/github-labels.js` lists the repo's labels (`gh label list --json name --limit 500`) and returns `{ missing: [names] }`. (3) `shiftwork github labels [--create]` (`packages/cli/bin/shiftwork.js`): prints each configured label with `✔ exists` / `✖ missing`, exits 1 when any is missing; `--create` creates only the missing ones with a colour and a description (`gh label create <name> --color … --description …`), never edits or deletes. (4) `run --dark-factory` (ticket 05) calls `checkLabels` at start and, when anything is missing, exits 1 with: `dark-factory: missing GitHub labels in <repo>: <names>. Create them: shiftwork github labels --create (see docs/guide.md "Dark-factory: labels")`. (4b) **Use the operator's installed `gh`.** Add an optional `github.gh` config key (path to the binary; default `gh` from `PATH`) and make `createGitHub` (ticket 01) run that binary, inheriting the environment so the operator's `gh auth login` session is used; Shiftwork never reads or stores a token and adds no HTTP client. (5) Guide: a "Dark-factory: labels" section in `docs/guide.md` and `docs/guide.uk.md` — what each label means and who sets it (you set `in`; Shiftwork sets `working` / `needs-info` / `done`), and step-by-step setup: install the GitHub CLI (https://cli.github.com) — Shiftwork uses it and its login, no token in the config — `gh auth login`, `gh auth status` to check, the `github` config block with an example, `shiftwork github labels --create`, then put the `in` label on an issue by a collaborator. Mention it in `skills/shiftwork/references/config.md` (then `npm run sync-skills`) and run `npm run llms`.
